# 全部回 200 的 API，前端怎麼知道出事了

前端同事來問你：每支 API 都是 200，他得去讀本文裡的欄位，才知道到底有沒有成功。

狀態碼是 API 對呼叫方說的第一句話。它說得清楚，呼叫方不用解析本文，就知道發生了什麼事。

## 用 ResponseEntity 指定狀態碼

直接回傳物件，Spring 預設回 200。想自己決定狀態碼，就回傳 `ResponseEntity`，它同時控制狀態碼與本文。新增成功，回 201 並帶回新建的資料：

```kotlin
@PostMapping
fun create(@RequestBody request: CreateSnippetRequest): ResponseEntity<Snippet> {
    val created = service.create(request)
    return ResponseEntity.status(HttpStatus.CREATED).body(created)
}
```

查詢單筆時，找不到就是 404，不要回 200 加一個空本文：

```kotlin
@GetMapping("/{id}")
fun get(@PathVariable id: Long): ResponseEntity<Snippet> =
    service.find(id)
        ?.let { ResponseEntity.ok(it) }
        ?: ResponseEntity.notFound().build()
```

這裡剛好用到 Kotlin 的空安全：`find` 回傳可為空型別，有值就包成 200，沒有值就走 404。

## 狀態碼的選擇原則

不需要記住所有狀態碼，掌握這幾個就能處理九成情況：

- 成功取得資料，回 200。
- 成功建立資源，回 201。
- 成功但沒有內容要回，例如刪除，回 204。
- 呼叫方送來的請求有問題，回 400。
- 找不到對應的資源，回 404。

別為了每種情境發明新規則。呼叫方的程式碼通常只認得這幾種。

目前錯誤的情況還只處理了一種。更多錯誤，包含請求資料不合法，留給後面幾期統一處理。下一封信，我們先把記憶體裡的資料換成資料庫，從資料類別怎麼對應資料表開始。
