# 五個端點怎麼寫，參數各用哪個註解拿

五個端點，十五個註解，每次寫都得回頭查哪個對應哪個。

其實只需要記一個原則：資料從哪裡來，就用對應的註解去拿。

## 五個端點，一個控制器

片段庫需要列出、查詢單筆、新增、更新、刪除。HTTP 方法與註解一一對應：`@GetMapping` 讀取，`@PostMapping` 新增，`@PutMapping` 更新，`@DeleteMapping` 刪除。整個控制器長這樣：

```kotlin
@RestController
@RequestMapping("/snippets")
class SnippetController(private val service: SnippetService) {

    @GetMapping
    fun list(@RequestParam language: String?) = service.list(language)

    @GetMapping("/{id}")
    fun get(@PathVariable id: Long) = service.get(id)

    @PostMapping
    fun create(@RequestBody request: CreateSnippetRequest) = service.create(request)
}
```

更新與刪除的寫法與這三個類似，這裡省略。

## 三個註解，三種來源

- 路徑參數用 `@PathVariable`，像 `/snippets/42` 裡的 42，用來指定要操作哪一筆資料。
- 查詢參數用 `@RequestParam`，像 `/snippets?language=kotlin` 裡的條件，用來篩選或分頁。
- 請求主體用 `@RequestBody`，通常是新增或更新時送來的 JSON，直接轉成一個物件。

為請求主體定義一個資料類別，是 Kotlin 很舒服的地方：

```kotlin
data class CreateSnippetRequest(
    val title: String,
    val language: String,
    val code: String,
    val tags: List<String> = emptyList(),
)
```

欄位有預設值，呼叫方可以省略；沒有預設值的欄位，缺少時反序列化會失敗。

## Kotlin 的可為空型別在這裡有用

上面的 `language: String?` 就是在告訴 Spring：這個查詢參數可以不傳。型別可為空，就是選填；寫成 `String`，就是必填，缺少時回 400。選填還是必填，直接寫在型別上，不用額外標註。
