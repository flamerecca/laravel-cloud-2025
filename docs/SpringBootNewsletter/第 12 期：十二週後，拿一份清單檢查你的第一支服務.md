# 十二週後，拿一份清單檢查你的第一支服務

十二週後，你手上多了一堆標註與設定，卻不知道自己的服務到底完不完整。

這是十二期系列的最後一封信。系列從一個剛產生的專案，走到有驗證、有統一錯誤格式、有測試的小服務。這封信不教新東西，只把走過的路收斂成一份可以直接對著專案檢查的清單。五個層次，十二個問題。答不出來的那一題，就是你接下來要補的功課。

## 專案建置

- 打開專案，你說得出建置檔、設定檔與進入點各自在做什麼嗎？
- `kotlin-spring` 與 `kotlin-jpa` 兩個外掛都已經啟用了嗎？

## 依賴注入與分層

- 類別需要的東西，都是從建構子傳進來，沒有在類別裡自己建立嗎？
- 控制器只負責接收請求與回應，業務邏輯放在服務類別裡嗎？

## API 設計

- 每個參數都用對了來源註解，選填的參數也在型別上標成可為空嗎？
- 新增回 201，找不到回 404，你的狀態碼會說話嗎？

## 資料庫整合

- Entity 能正常啟動，查詢用的是清楚的方法名稱或明確的查詢嗎？
- 你清楚 H2 只是開發用，正式環境需要另一個獨立的資料庫嗎？

## 確認與測試

- 驗證規則是否都實際送過錯的資料，確認它真的擋得住？
- 全服務的錯誤，是否都是同一種格式，內部細節只留在日誌裡？
- 核心端點是否至少有一個測試，每次改版都會自動跑？
- 你能不看筆記，說出任何一個測試失敗時該先看哪裡嗎？

## 這個系列沒有講的

清單通過，代表第一支服務有了完整的骨架。離真的上線，還有幾塊是這個系列刻意沒碰的，全部列入後續待辦：

- Spring Security 的完整權限系統，也就是登入與授權。
- Spring Cloud 與微服務的拆分與治理。
- Actuator 與應用程式的監控。
- 編譯成原生執行檔的 GraalVM。

如果你想往協程與正式環境的方向走，可以接續另一個專談 Spring Boot 協程的系列。

回頭看第一封信的問題：剛產生的專案，哪些檔案可以先不用管。現在你應該說得出每一個檔案是做什麼的了。

謝謝你讀完這十二封信。身邊如果有朋友正在學 Spring Boot，把這份清單轉給他。

回信告訴我，這十二題裡你的專案答不出來的是哪一題。如果這封信是朋友轉給你的，歡迎訂閱，每週一封。
