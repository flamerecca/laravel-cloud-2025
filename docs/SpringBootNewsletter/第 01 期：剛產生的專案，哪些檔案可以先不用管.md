# 剛產生的專案，哪些檔案可以先不用管

專案產生完，資料夾裡躺著一堆檔案，沒有一個你敢刪，也沒有一個你敢改。

這封信只做一件事：告訴你第一天只需要看懂三個地方，其他的先放著。接下來十二封信，我會用一個叫「片段庫」的小服務當範例，一個存放與搜尋程式碼片段的後端。

## 第一個地方：build.gradle.kts

這個檔案宣告專案用哪些外掛與依賴。第一天只需要認得兩類東西：

```kotlin
plugins {
    kotlin("jvm") version "..."
    kotlin("plugin.spring") version "..."
    id("org.springframework.boot") version "..."
}

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web")
    implementation("org.jetbrains.kotlin:kotlin-reflect")
    implementation("com.fasterxml.jackson.module:jackson-module-kotlin")
}
```

`spring-boot-starter-web` 帶來 Web 功能與內嵌的伺服器，不用另外裝 Tomcat。`kotlin-reflect` 與 `jackson-module-kotlin` 讓 Spring 與 JSON 序列化認得 Kotlin 的類別。其他沒看過的行，先當它們是產生器替你準備的。

## 第二個地方：設定檔

`src/main/resources/application.properties` 剛產生時幾乎是空的。之後資料庫連線、埠號這類執行期設定，都會放在這裡。現在只需要知道它在哪。

## 第三個地方：進入點

```kotlin
@SpringBootApplication
class SnippetVaultApplication

fun main(args: Array<String>) {
    runApplication<SnippetVaultApplication>(*args)
}
```

`runApplication` 啟動整個應用程式，`@SpringBootApplication` 讓 Spring 自動設定，並掃描這個類別所在套件底下的所有類別。這一點很實用：之後你新增的類別，必須放在這個套件之下，Spring 才找得到它。

## 可以先放著的東西

測試資料夾、Gradle wrapper 的檔案、`.gitignore`，有它們很方便，沒有它們服務一樣跑得動。等後面幾期用到，再回頭看就好。

建置檔裡有一行 `kotlin("plugin.spring")`，很多人看了一眼就跳過。下一封信，我們來看它替你擋掉了什麼麻煩。

回信告訴我，你打開專案後最不敢動的是哪一個檔案。如果這封信是朋友轉給你的，歡迎訂閱，每週一封。
