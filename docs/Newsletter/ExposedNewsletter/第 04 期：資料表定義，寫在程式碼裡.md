# 資料表定義，寫在程式碼裡

資料表是在資料庫工具裡建的，程式碼裡卻沒有任何一個地方，記著它長什麼樣子。

等到有人改了欄位名稱，你的程式要跑到那一行才知道壞了。Exposed 的做法，是把資料表的樣子直接寫進 Kotlin。

## 一個 object，就是一張資料表

```kotlin
object Snippets : IntIdTable("snippets") {
    val title = varchar("title", 100)
    val language = varchar("language", 30)
    val code = text("code")
}
```

`IntIdTable` 是 `Table` 的一個子類別，替你加好一個自動遞增的整數主鍵欄位 `id`。括號裡的 `"snippets"` 是資料庫裡的實際資料表名稱。

每個 `val` 對應一個欄位：型別、名稱、長度都寫在這裡。這個 object 之後會被所有查詢引用，所以欄位名稱只會存在於一個地方，打錯就是編譯錯誤。

## 建立資料表

資料表定義只是描述，要讓資料庫真的有這張表，需要建立它：

```kotlin
transaction {
    SchemaUtils.create(Snippets)
}
```

`SchemaUtils.create` 會依定義產生建表語法並執行，已經存在就略過。記得它要在 `transaction` 區塊裡，上一封信講過原因。

## 一個重要的界線

`SchemaUtils` 很適合學習與開發階段，讓你不用另外寫建表腳本。正式環境的資料表變更，例如加欄位、改型別，需要有紀錄、可還原的遷移工具來管理，不能靠程式啟動時自動建表。這個系列不涵蓋遷移工具，只提醒你這條界線在哪裡。
