# 一個片段，多個標籤

你把標籤存成一個用逗號分隔的字串，一直都很方便，直到有人要你列出某個標籤底下的所有片段。

這時你會發現，要在字串裡找某個標籤，沒有任何索引能幫你。這個便利，只在資料量很小、需求很單純的時候成立。

## 為什麼字串撐不住

用字串存標籤，三個問題會陸續出現：查詢某個標籤時，得對每一列做字串比對，速度與準確度都不好；改一個標籤的名稱，要掃過所有列去改；同一個標籤可能出現拼法不一致的版本，沒有任何機制擋下。

## 拆成三張資料表

多對多的標準做法，是多一張中介資料表，記錄「哪個片段掛了哪個標籤」：

```kotlin
object Tags : IntIdTable("tags") {
    val name = varchar("name", 50).uniqueIndex()
}

object SnippetTags : Table("snippet_tags") {
    val snippet = reference("snippet_id", Snippets)
    val tag = reference("tag_id", Tags)
    override val primaryKey = PrimaryKey(snippet, tag)
}
```

標籤名稱設成唯一，擋下拼法不一致。中介資料表的主鍵是兩個外鍵的組合，同一個片段不會重複掛上同一個標籤。

## 在 DAO 裡讀寫

用 `via` 把中介資料表接起來：

```kotlin
class Snippet(id: EntityID<Int>) : IntEntity(id) {
    companion object : IntEntityClass<Snippet>(Snippets)
    var title by Snippets.title
    var tags by Tag via SnippetTags
}
```

讀取直接用 `snippet.tags`，新增標籤時，把標籤設給 `snippet.tags`，Exposed 會替你處理中介資料表的寫入。

這個設計比一個字串欄位多了維護成本，要多寫一些宣告與關聯。換來的是查詢、更新與一致性都由資料庫幫你守住。
