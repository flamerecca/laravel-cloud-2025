# 第一次連上資料庫，只要一行

你加了一堆依賴，還是不確定缺了哪一個，也不確定連線字串該怎麼寫。

這封信只做一件事：用最少的依賴，連上一個不用安裝的內嵌資料庫。

## 最小的依賴組合

Exposed 是拆成好幾個模組的，第一次只需要三個：

```kotlin
dependencies {
    implementation("org.jetbrains.exposed:exposed-core:1.5.1")
    implementation("org.jetbrains.exposed:exposed-jdbc:1.5.1")
    implementation("com.h2database:h2:<H2 版本>")
}
```

`exposed-core` 放資料表定義與查詢的基礎類別，`exposed-jdbc` 負責透過 JDBC 真的和資料庫講話，H2 則是一個跑在記憶體裡的資料庫，不用另外安裝。Exposed 的模組版本號要一致，混用不同版本很容易出現找不到類別的錯誤。

## 一行連線

```kotlin
import org.jetbrains.exposed.v1.jdbc.Database

fun main() {
    Database.connect("jdbc:h2:mem:snippetvault;DB_CLOSE_DELAY=-1", driver = "org.h2.Driver")
    println("連線資訊已登記")
}
```

`Database.connect` 做的是登記連線資訊。真正開出連線，要等到你第一次執行資料庫操作的時候，這件事下一封信會談。連線字串裡的 `DB_CLOSE_DELAY=-1`，是讓記憶體資料庫在連線關閉後不要立刻消失，學習階段很方便。

## 想換資料庫

如果之後要換成 MySQL 或 PostgreSQL，需要改的只有兩處：連線字串與驅動依賴。查詢與資料表定義的程式碼完全不用動。這是用函式庫描述查詢，不必手寫各家資料庫方言的好處之一。

連線登記好了，但還沒有任何東西真的跑起來。下一封信，我們看為什麼 Exposed 的每個操作，都要包在一個叫 `transaction` 的區塊裡。

回信告訴我，你最後想接的是哪一種資料庫。如果這封信是朋友轉給你的，歡迎訂閱，每週一封。
