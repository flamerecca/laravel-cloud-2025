# DSL 還是 DAO，該選哪一個

同一個專案裡，一半的檔案用 DSL，一半用 DAO，沒有人說得出為什麼。

兩種寫法都能完成工作，選擇其實沒有標準答案。但有判斷依據，也有約定方式，這封信把它整理出來。

## 同一個需求，兩種寫法

需求：取出所有 Kotlin 片段的標題。

DSL 的寫法：

```kotlin
transaction {
    Snippets.selectAll()
        .where { Snippets.language eq "kotlin" }
        .map { it[Snippets.title] }
}
```

DAO 的寫法：

```kotlin
transaction {
    Snippet.find { Snippets.language eq "kotlin" }
        .map { it.title }
}
```

看起來差不多，差異在於中間的東西。DSL 手上拿的是一列資料，取值要用 `it[欄位]`。DAO 手上拿的是 `Snippet` 物件，取值像讀取屬性，還可以呼叫你加在 Entity 上的方法。

## 三個比較角度

- 可讀性：物件導向的領域邏輯多時，DAO 讀起來更自然。查詢複雜、需要連接與聚合時，DSL 更接近 SQL，更直接。
- 彈性：DSL 可以只取你需要的欄位，也容易寫出報表型的查詢。DAO 預設載入整個物件，需要時才再細修。
- 除錯：兩者最終都產生 SQL，除錯方式相同，都靠 SQL 日誌。

## 怎麼選

一個簡單的起點：以物件為中心、大多是新增與修改單筆資料的功能，用 DAO。以查詢為中心、需要連接多張資料表、做統計與報表的功能，用 DSL。

兩種可以在同一個專案混用，兩者共用同一份資料表定義。但團隊要約定清楚界線，例如「寫入用 DAO，報表用 DSL」，不要讓每個人各憑喜好，過幾個月之後誰也讀不懂。
