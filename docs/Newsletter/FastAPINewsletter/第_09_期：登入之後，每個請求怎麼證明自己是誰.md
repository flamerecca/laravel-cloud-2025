# 登入之後，每個請求怎麼證明自己是誰

我習慣的是 Laravel 的 `Auth::user()`，一行就拿到目前登入的人。轉到 FastAPI 之後，我花了一個下午找這一行在哪裡，最後的答案是：它沒有內建。

FastAPI 不替你做認證，但它留了三個接口：密碼要自己雜湊，標記要自己簽發，路由要自己用依賴保護。三塊都接上，就是一條完整的登入流程。這封信只走最短的一條路，用 JWT。

先用一句話交代 JWT：它是伺服器簽名後交給用戶端的字串，用戶端之後每個請求都帶著它回來，伺服器驗過簽名，就知道這個請求是誰發的。

## 第一塊：密碼不能存明碼

資料庫裡只放雜湊後的結果，登入時拿使用者輸入的密碼去比對。也不要用單純的 SHA，它設計得太快，被暴力破解時反而吃虧。

官方文件目前建議用 `pwdlib` 處理密碼，推薦 Argon2：

```python
from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()
hashed = password_hash.hash("my-password")
password_hash.verify("my-password", hashed)  # True
```

安裝指令是 `uv add "pwdlib[argon2]"`。官方文件把 `passlib` 只留給讀取舊雜湊的情境，新專案不用特地選它。

## 第二塊：登入成功就簽一張標記

JWT 的 payload 只放兩樣東西：`sub` 放使用者識別，`exp` 放到期時間。其他資料別塞進去，因為 payload 只是編碼，任何人拿到標記都讀得到。簽發用 `PyJWT`，安裝指令是 `uv add pyjwt`：

```python
import jwt
from datetime import datetime, timedelta, timezone

def create_access_token(username: str) -> str:
    exp = datetime.now(timezone.utc) + timedelta(minutes=30)
    payload = {"sub": username, "exp": exp}
    return jwt.encode(payload, SECRET_KEY, algorithm="HS256")
```

這裡的 `SECRET_KEY` 是簽名用的密鑰，範例為了精簡先當成現成的變數。實際專案裡它不能寫死在程式碼，更不能進版本控制，第 11 期談環境設定時會專門處理。

登入端點負責驗密碼、呼叫上面這個函式：

```python
@app.post("/token")
def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user = get_user(db, form.username)
    if not user or not password_hash.verify(form.password, user.hashed_password):
        raise HTTPException(status_code=401, detail="帳號或密碼錯誤")
    token = create_access_token(user.username)
    return {"access_token": token, "token_type": "bearer"}
```

`OAuth2PasswordRequestForm` 會從表單欄位讀 `username` 與 `password`，所以這支端點收表單欄位，用 JSON 送會失敗。`get_user` 與 `db` 在這裡代表你自己的使用者查詢，用 SQLModel 或假資料都行。

## 第三塊：用依賴取出目前使用者

這一塊最接近 `Auth::user()`。先提醒一句，`Depends` 是 FastAPI 讓你在函式簽章上宣告「我需要某個函式的回傳值」的機制，框架會在請求當下替你呼叫。

`OAuth2PasswordBearer` 負責從 `Authorization` 標頭取出標記，`get_current_user` 再接手驗證：

```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
    except InvalidTokenError:
        raise HTTPException(status_code=401, headers={"WWW-Authenticate": "Bearer"})
    return get_user(db, payload["sub"])
```

`tokenUrl="token"` 只是宣告：客戶端要去哪個網址換標記。它是相對網址，等同 `./token`，不會替你建立端點。端點就是上一段寫的 `/token`。

任何路由要保護，多宣告一個依賴就好：

```python
@app.get("/me")
def read_me(user: Annotated[User, Depends(get_current_user)]):
    return user
```

沒帶標記就呼叫 `/me`，官方文件的說法是 `OAuth2PasswordBearer` 看不到 `Authorization` 標頭或沒有 Bearer 標記時，會直接回 401。標記過期或簽名不符，會落到 `get_current_user` 裡的 `InvalidTokenError`，同樣回 401。

另外，`/docs` 頁面會多出一個 Authorize 按鈕，受保護的路由旁邊有鎖頭圖示，輸入帳號密碼就能在瀏覽器裡直接試。

這三塊合在一起，就是 FastAPI 裡的 JWT 認證：雜湊保護密碼，JWT 讓每個請求自帶身分，依賴把驗證收進一個函式。

## 這封信帶走的東西

FastAPI 的認證要自己組，但只有三個零件：`pwdlib` 雜湊密碼，`PyJWT` 簽發與驗證標記，`OAuth2PasswordBearer` 加 `get_current_user` 保護路由。

這封信刻意沒有碰 OAuth 第三方登入與 Refresh Token，兩者都列在後續待辦。

功能都有了，下一封要看的是怎麼在不開伺服器的情況下測它，包括怎麼讓 `get_current_user` 在測試裡換成假的使用者。

回信告訴我，你現在的專案用的是哪一種認證方式，Session、JWT，還是交給閘道處理。如果這封信是朋友轉給你的，歡迎訂閱，每週一封。

## 待實測項目

我無法執行程式碼，以下項目請在 Python 3.12 與目前 FastAPI 版本實測後再發信：

1. 所有程式碼片段需串成一個可執行的檔案實際啟動。稿中的 `SECRET_KEY`、`db`、`get_user`、`User`、`HTTPException`、`InvalidTokenError` 等名稱，在正文片段裡省略了匯入與定義，實測時要補齊。
2. `OAuth2PasswordRequestForm` 收表單，需安裝 `python-multipart`，此依賴要求本次未查證，需實測確認。
3. 登入端點的失敗狀態碼稿中寫 401。官方範例頁面的寫法本次未逐行確認，需對照官方頁面與實測。
4. 未帶標記呼叫 `/me` 時：狀態碼 401 有官方文字佐證，但回應本文內容與是否帶 `WWW-Authenticate` 標頭，官方頁面未寫明，必須用 `curl -i` 實測後再補進稿中。
5. `get_current_user` 內標記過期與簽名不符是否都落入 `InvalidTokenError`，需各自用過期標記與竄改標記實測。
6. `/docs` 的 Authorize 按鈕：官方文件有說明按鈕與鎖頭存在，但按鈕實際送出請求的行為官方頁面未明講，需在 `/token` 寫好後實測登入流程。
7. `password_hash.verify` 回傳 `True` 的註解需實測確認回傳型別。
8. `pwdlib[argon2]` 與 `pyjwt` 的安裝指令來自官方 OAuth2 JWT 頁面現況，發信當天再看一次頁面，確認推薦套件未變更。
9. 稿中「`passlib` 只留給讀取舊雜湊」依官方頁面現況，發信前再確認。
10. 稿中「SHA 太快，暴力破解吃虧」屬通用安全原則，未針對官方文件查證，審稿時請確認措辭。
