# 十二週後，你自己就是判斷者

這是「Filament 客製化實戰」系列的第 12 期，也是最後一期。如果你是中途才加入的讀者，先簡單交代一句：這段時間我們一路示範怎麼在 Filament 的預設機制之外動手，從欄位呈現、表格互動，一路做到自訂頁面、跳出 Schema 機制、甚至接上即時推播。今天不教新技巧，我們要做的是把前面十一期收攏成一張你以後卡關時可以直接查的表。

## 十二週前的那句話

這個系列的起點，其實接在 iTHome 鐵人賽《Laravel Filament 從入門到實戰》完賽總結的最後一句話。那篇總結了 Filament 有兩類自己不擅長的情境，然後把「該怎麼繞道」這個判斷，交還給讀者自己。

老實說，那句話交還得有點早。知道「該繞道」和知道「怎麼繞」中間，隔著許多的技術細節。這段時間要做的事，就是把那個交還的判斷，一步一步具體接回來。

## 一張分層判斷清單

如果你只記得這封信的一件事，希望是這張表背後的邏輯：客製化的深度，跟著需求「離開框架預設多遠」往下分層。

最淺的一層，是欄位與表格呈現本身。你要改的只是一個值怎麼顯示、一欄怎麼排序、一個篩選條件怎麼運作。這種需求的徵兆很好認：你想要的效果，跟現有元件做的事情本質上是同一件事，只是預設的樣子不合用。這一層我們前幾期示範過怎麼動手，改的是呈現邏輯，不是骨架。

中段的一層，是自訂頁面與視覺分層。當你發現需求已經不是「這個元件長得不一樣」，而是「這個畫面的資訊架構跟 Filament 預設的 CRUD 頁面對不上」，你就進到這一層了。徵兆是你會發現自己在畫面上想放的東西，用現有的資源頁面怎麼排都彆扭，那通常代表你需要的是一個自訂頁面，而不是硬塞進去的客製元件。

最深的一層，是跳出 Schema 機制，接上即時推播這類需求。這一層的徵兆很明確：你要的東西本質上不是「畫面怎麼排」，而是「資料怎麼即時流動」，或者「這個互動邏輯已經超出表單提交、重新整理這種一問一答的模式」。走到這裡，代表你要處理的已經不只是 Filament 的呈現層，而是它跟底層事件、連線機制怎麼接軌。

還有兩期不屬於這條深度軸線，但同樣是這套判斷工具的一部分：封裝，還有效能取捨。這兩件事發生在你做完客製化之後，屬於另一個維度的責任。封裝決定你的客製化能不能被下一個專案重複用，效能取捨決定你付出的複雜度換來的效果值不值得。它們不回答「該做到多深」，回答的是「做完之後怎麼收尾」。

下次卡關的時候，先問自己這個需求離框架預設多遠，再對照這四層找位置，不需要重新翻十一封信。

## 這句話兌現了多少

走完這十二週，「該怎麼繞道」這個判斷，具體示範到什麼程度了。坦白講，大部分常見的情境，你現在應該已經有清楚的路徑可以走。欄位不夠用、表格互動不夠、頁面骨架卡住、甚至需要跳出 Schema 機制處理即時性的需求，這些我們都動手做過一遍，你手上有可以照著改的範例，也有前面那張表告訴你該往哪個方向找答案。

但不諱言，有些需求就是不該留在這裡。有些客製化的代價，不是「難不難」的問題，是「值不值得」的問題。當你發現一個需求要撐起來，得動用到最深那層的技巧，而且改動的範圍已經逼近重寫一個框架該做的事，那個當下最誠實的判斷可能是換工具，而不是把 Filament 撐到極限。這不是承認失敗，是把「判斷交還給你」這句話真正落實：判斷不是無條件地一路客製化到底，判斷也包含知道什麼時候該放手。

## 怎麼做只是查表

十二週走到這裡，如果要留一句話給你，會是這句：客製化的第一個問題永遠不是怎麼做，是這個需求該不該留在這裡。想清楚這件事之後，怎麼做只是對照分層清單查表而已。

技術細節你隨時可以回頭翻，但判斷力這件事沒辦法回頭翻。上一個系列結束的時候，這個判斷還握在文章手上，只是先告訴你「交還給你」。這十二週做的，就是把判斷實際地、一次一次地，搬回你手上。現在再遇到一個需求該不該客製化、該客製化到多深，做這個判斷的人已經不是這個系列，是你自己。

謝謝你讀完這整個系列。如果這十二封信對你手上的專案有幫助，歡迎分享給同樣在用 Filament 這套框架的朋友。這個系列到這裡正式告一段落。
