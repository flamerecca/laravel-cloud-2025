# 卡關不是你不熟框架，是你撞上了邊界

你有沒有遇過這種時刻：一個需求聽起來明明不複雜，你打開 Filament 的文件，開始一頁一頁翻元件清單，Table、Form、Widget、Action，逐一比對，確認自己是不是漏看了哪個參數。翻完一輪找不到，你會做的第一件事通常不是放棄，而是換個關鍵字再搜一次，也許剛剛的用詞不對，也許官方藏了一個沒寫進導覽選單的頁面。

十分鐘過去，你開始懷疑自己是不是漏學了什麼版本更新，或者這件事其實有個隱藏參數，只是你還沒找到門路。於是你打開 GitHub Discussions，打開 Discord，搜尋別人有沒有問過一樣的問題。有時候真的會挖到一段某個人三年前留的解法，你如獲至寶；更多時候是一片安靜，只有幾個人跟你問了一樣的問題，卻沒有人回。

那種焦躁感很特別，它不是「這個很難」帶來的挫折，而是「我是不是不夠熟」帶來的自我懷疑。你會開始想，是不是自己書讀得不夠仔細，是不是別人都知道一個你不知道的技巧。

我想先把這個念頭攔下來，因為它多半是錯的。

## 這不是你不知道，是這件事本來就不在框架的預設劇本裡

「我不知道怎麼做」和「這件事本來就不在框架預設的做法裡」，是兩件完全不同的事，也需要完全不同的解法。前者是知識缺口，靠查資料、看文件、問人就能補上，你缺的只是一個關鍵字或一篇教學。後者不是缺口，是邊界，靠查資料是補不上的，因為根本沒有那份文件在等你找到，你需要的是另一種判斷力，判斷這件事該用什麼層級的工具去處理。

會分不清這兩者，是很自然的事。因為卡住的當下，兩種情況給你的生理反應幾乎一樣，都是盯著螢幕，都是搜尋框裡打了又刪、刪了又打。你沒辦法光靠「卡住的感覺」分辨自己站在哪一邊，這正是這系列想解決的問題。

在《Laravel Filament 從入門到實戰》鐵人賽完賽總結裡提過，Filament 有兩類情境特別容易讓人卡關：高度客製化的視覺互動，以及非典型的後台操作型態。這兩類需求不是 Filament 做不到，而是它們本來就落在框架預設劇本之外，需要你自己動手把邏輯接上去。這系列接下來要做的事，就是把「該怎麼繞道」這個判斷具體地示範出來，帶你走一遍該怎麼走，也讓你看清楚走到哪一步，這件事就不再歸框架管了，得靠你自己的程式碼接手。

## 先問一句話：這個需求離 Filament 的預設做法有多遠

如果這系列只能留給你一件事，我希望是這句自問：這個需求，離 Filament 預設的做法有多遠？

「多遠」聽起來抽象，但其實有具體徵兆可以判斷，不需要靠直覺硬猜。你可以先問自己，這件事是不是只是在調整一個既有元件的顯示方式，比如換個排列、加個顏色、調整欄位顯示的條件，這種通常離得很近，翻一下文件或設定選項多半就能解決。如果不是，再往下問，這件事是不是需要一個全新的互動邏輯，元件本身沒問題，但你要它做的事，框架沒有預留這個開關，這時候距離就拉開了一截，你可能得靠一些組合技巧才能達成。

如果連這一層都不夠，代表你需求的是框架壓根沒設計過的操作型態，這種時候已經不是找開關的問題，而是你得從更底層的機制開始理解，自己把那條路鋪出來。

這個距離感很重要，因為它跟代價直接掛鉤。離得越遠，你要動用的工具就越底層，要理解的機制越多，之後要維護的程式碼也越複雜。先花一點時間判斷距離，能幫你避免一件很虧的事，就是每次卡關都直接跳進最底層硬解，明明用一個小技巧就能解決的問題，卻花了兩小時研究框架的內部運作。判斷距離這件事本身就有價值，它幫你把力氣用在對的地方。

這一期我刻意沒有放任何程式碼，這是有意的安排，不是我想留一手。因為在動手之前，我更想先把這套判斷的角度立起來，讓你在真正遇到卡關的那一刻，能先問這句話，而不是直接埋頭硬幹。程式碼要接回這套判斷邏輯，會從下一期開始，一步一步示範。

看完這篇，如果你腦中已經浮現一個具體卡住你的需求，不管是視覺互動還是操作邏輯，回信告訴我吧。接下來幾期，我會挑幾個讀者實際回報的案例來示範怎麼判斷、怎麼走這條路。說不定，你這封信裡寫的那個需求，就會變成某一期的主角。
