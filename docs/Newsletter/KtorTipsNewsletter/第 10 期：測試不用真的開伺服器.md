# 測試不用真的開伺服器

每次跑測試之前，要先 `docker compose up`，等資料庫起來，再跑測試，再把它關掉。久了，沒有人想跑測試。

Ktor 的路由測試不需要這些。如果你習慣 Laravel 的 Feature Test，`testApplication` 就是它的對應物：它在記憶體內啟動你的應用程式，不占用實際的 Port，也不經過網路。

## 最小的測試

```kotlin
@Test
fun `GET orders 回 200`() = testApplication {
    application { module() }
    val response = client.get("/orders")
    assertEquals(HttpStatusCode.OK, response.status)
}
```

`application { }` 區塊裡載入你要測的模組，`client` 是內建的測試用 client，發請求、檢查狀態碼與本文，跟平常一樣。

## 一個容易誤用的地方

如果路由接收 JSON，測試 client 端也需要安裝 ContentNegotiation，否則 `setBody` 不知道怎麼把物件變成 JSON：

```kotlin
val client = createClient { install(ContentNegotiation) { json() } }
val res = client.post("/orders") {
    contentType(ContentType.Application.Json)
    setBody(CreateOrder(customerId = 1))
}
```

伺服器端與 client 端是兩組各自的設定，裝了一邊不代表另一邊也有。

## 把資料庫換成假的

要讓測試不依賴真的資料庫，關鍵在讓路由接收依賴，而不是自己建立依賴。把路由設定拆成一個接收 Repository 的函式：

```kotlin
fun Application.configureRouting(repo: OrderRepository) {
    routing { orderRoutes(repo) }
}
```

正式環境的 `module()` 傳入真的實作。測試裡傳入記憶體版本：

```kotlin
testApplication {
    application {
        install(ContentNegotiation) { json() }
        configureRouting(FakeOrderRepository())
    }
    // ...
}
```

這就是上一個主題，物件組裝，在測試時派上用場的地方：依賴是從外面傳進來的，要換就換。
