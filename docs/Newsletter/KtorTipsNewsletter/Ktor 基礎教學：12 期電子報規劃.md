# Ktor 基礎教學：從第一支路由到敢放進正式環境

一份三個月、12 期的電子報企劃。寫給讀過 [[為什麼我開始把 Ktor 放進後端選型清單]]，或已經有 Laravel、Spring Boot、Node.js 後端經驗，決定動手試 Ktor 的工程師。

選型介紹文回答的是「要不要放進清單」。這個系列接著回答下一個問題：決定要試之後，第一個月會撞到什麼，每一個坑怎麼繞過去。每一期對應一個具體的卡關情境，十二期湊起來剛好是一條從 `main()` 到 Docker 映像檔的路線。

每一期是一封獨立的信，不假設你追過前面幾期，每封信只講一件事，篇幅控制在一次通勤或一杯咖啡的時間看得完。

## 與第 0 期的待確認事項

寫第 0 期時留下幾處，在撰寫基礎教學前需要先查證，否則會在系列裡互相矛盾。

1. **`async` 範例的編譯性**：第 0 期的 handler 範例直接在路由區塊內呼叫 `async { }`。Ktor 3.x 的路由 handler 接收者是否為 `CoroutineScope` 需要實測，若不是，需要用 `coroutineScope { }` 包起來。這影響第 6 期的示範，也可能需要回頭修第 0 期。
2. **Exposed DSL 寫法**：第 0 期使用 `.select { }` 寫法，新版 Exposed 已改為 `selectAll().where { }`，1.0 之後套件路徑也有調整。第 7 期動筆前先決定鎖定哪個版本。
3. **壓測數字的來源**：第 0 期的壓測表格是團隊內部數字，基礎教學不引用，也不重新宣稱效能差距。
4. **Plugin 原始碼承諾**：第 0 期結尾預告「下一期拆 Plugin 機制原始碼」，對應第 4 期。若第 4 期要調整深度，同步更新第 0 期的預告文字。

## 逐期企劃

逐期完整規格見同層 `規格書` 資料夾，每期一個檔案。以下是各期的摘要，方便整體審視節奏。

### 第 1 期：十行程式碼跑起一個服務，然後看它缺了什麼

讀者拿 Ktor 專案產生器建了專案，或照文件貼了十行 `main()`，服務跑起來了，但不知道哪些檔案是必要的、哪些是樣板。這期逐行拆最小專案，並用一句話帶過其他框架預設有、這裡沒有的東西，為後面幾期埋下「缺了什麼要自己補」的線索。

### 第 2 期：路由寫在哪裡，路徑參數拿不到怎麼辦

示範 `routing` 區塊、`route` 分組、路徑參數與查詢參數的取法，以及把路由拆成 `Route` 擴充函式放進獨立檔案。重點是取參數時 `null` 的處理，這是新手最常踩的地方。

### 第 3 期：JSON 進來出去，欄位對不上時發生什麼事

安裝 ContentNegotiation 與 kotlinx.serialization，示範 `@Serializable`、缺欄位、多欄位、型別不符三種情況各自的行為，以及要不要設定忽略未知欄位的取捨。

### 第 4 期：install() 一下，你的請求就多了一層

說明 Plugin 在請求管線上的位置，示範寫一個記錄請求耗時的自訂 Plugin，並稍微看一眼 `install` 背後的原始碼，回應第 0 期的承諾。

### 第 5 期：例外丟出去之後，使用者看到的是什麼

預設行為是回 500 並可能洩漏細節。示範 StatusPages 針對不同例外對應不同狀態碼，並約定一個全服務統一的錯誤回應格式。

### 第 6 期：handler 裡的 suspend，到底讓出了什麼

用一個故意在 handler 裡 `Thread.sleep` 的例子，對照 `delay`，看出差別。補上 `coroutineScope` 與 `async` 平行查詢的正確寫法，與阻塞呼叫該放進哪個 Dispatcher。

### 第 7 期：資料庫連線，在協程裡該怎麼開

接 Exposed 與 HikariCP，示範表定義、基本 CRUD、協程友善的交易寫法，並用 for 迴圈裡一筆一筆查關聯資料的 N+1 例子，說明 Ktor 不會替你擋下這種錯誤。

### 第 8 期：物件越來越多，誰來負責 new

從手動組裝的 `module()` 函式出發，在不引入工具與引入 Koin 之間給出判斷條件。重點是什麼時候手動組裝就夠，不預設一定要裝容器。

### 第 9 期：登入之後，每個請求怎麼證明自己是誰

示範 JWT 簽發與驗證、`authenticate` 區塊包住路由、從 `call.principal` 取出使用者。刻意不涵蓋 OAuth 與第三方登入。

### 第 10 期：測試不用真的開伺服器

示範 `testApplication` 與測試用 client，測一支路由的狀態碼與回應本文，並用第 8 期的做法把真實資料庫換成假的。

### 第 11 期：同一份程式，怎麼在三個環境跑起來

示範 `application.conf` 與環境變數覆寫、`buildFatJar`、最小 Dockerfile，並提醒設定檔不要把密鑰寫死。

### 第 12 期：十二週後，拿一份清單去評估你的第一支服務

不教新技巧。把前 11 期收斂成「專案起手、請求處理、資料與依賴、上線準備」四個層次的檢查清單，同時誠實列出這個系列沒有涵蓋的東西。

## 給撰寫每一期正文時的提醒

1. **篇幅落在 800 到 1500 字**，超過時先檢查是不是塞了不只一個重點，收斂重點，不要靠壓縮句子硬塞。
2. **不用系列連載慣用的「開場、小結」骨架式段落**，一封信讀起來該像一封信。
3. **不假設訂閱者看過前面任何一期**，要提到之前講過的東西，用一句話帶過就好。
4. **語氣口語**，直接對讀者說話，像寫信給一個具體的人。
5. **每一期只服務一個具體的卡關情境**，動筆前先確認這期解決的是「卡關的人」欄位裡那個人的哪一個問題。
6. **避免「不是…而是…」句型**，這是長文寫作已經明確要避開的 AI 腔。
7. **程式碼一律可實際編譯**，動筆前用對應版本實測，不憑記憶寫。每段程式碼不超過 15 行。
8. **統一用詞**：外掛一律寫 Plugin，協程用「協程」，不使用「技術棧」，一律用「技術堆疊」。
