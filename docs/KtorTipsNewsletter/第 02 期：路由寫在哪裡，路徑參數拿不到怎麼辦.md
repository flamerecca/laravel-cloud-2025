# 路由寫在哪裡，路徑參數拿不到怎麼辦

打開一個 Ktor 專案，`routing` 區塊長到兩百行，裡面塞著十幾個資源的所有路由，再也沒有人想動它。這是新手專案最常見的樣子，原因很單純：Ktor 的路由是普通程式碼，沒有人替你約定放在哪裡。

## 把路由拆成擴充函式

路由是 `Route` 上的區塊，所以可以寫成它的擴充函式，一個資源一個檔案，再由 `routing` 呼叫：

```kotlin
fun Route.orderRoutes() {
    route("/orders") {
        get { call.respondText("list") }
        get("/{id}") { call.respondText("order ${call.parameters["id"]}") }
    }
}

fun Application.module() {
    routing { orderRoutes() }
}
```

`route("/orders") { }` 做路徑前綴與分組，裡面的路徑會接在前綴後面。因為只是函式，你也可以用迴圈產生路由，或把共用的前綴包成一個輔助函式。

## 路徑參數：路徑裡有，不保證能用

`/orders/{id}` 的 `id` 一定存在，不然路由根本比對不到。真正的問題是它不保證是數字。最常見的寫法是這樣：

```kotlin
val id = call.parameters["id"]!!.toLong() // 路徑是 /orders/abc 就會丟例外
```

請求 `/orders/abc`，`toLong()` 丟出例外，沒人處理就是 500。使用者只是傳了一個壞參數，卻看到伺服器壞掉的訊息。

比較穩的寫法是自己轉換，轉不了就提早回應：

```kotlin
get("/{id}") {
    val id = call.parameters["id"]?.toLongOrNull()
        ?: return@get call.respond(HttpStatusCode.BadRequest, "id 必須是數字")
    call.respondText("order $id")
}
```

另一個選擇是 `getOrFail<Long>("id")`，缺少或轉不了時它會丟出特定例外，搭配之後會談的統一例外處理，可以一次對應成 400。

## 查詢參數：可選的，要給預設值

問號後面的查詢參數通常是可選的，取不到就是 `null`，這是正常情況。分頁參數是典型例子：

```kotlin
val page = call.request.queryParameters["page"]?.toIntOrNull() ?: 1
val size = (call.request.queryParameters["size"]?.toIntOrNull() ?: 20).coerceIn(1, 100)
```

注意 `size` 後面的 `coerceIn`。數值範圍要自己限制，不然有人傳 `size=1000000`，整張資料表就被撈出來了。

## 跟註解式路由的差別

如果你習慣用註解宣告路由，這裡看起來會有點散。差別在於 Ktor 的路由是可以用函式拆、用迴圈產生的程式碼，也因此，檔案該放在哪裡沒有人替你規定，要靠團隊自己約定。
