# 同一份程式，怎麼在三個環境跑起來

有一天，資料庫密碼不小心跟著程式碼推進了 Git 儲存庫。團隊花了一個下午輪替所有密鑰。

組態是會隨環境改變的值，資料庫位址、密鑰、Port，程式碼不該寫死它們。這封信走一遍 Ktor 處理組態與部署的最短路徑，從檔案一路到容器。

## 組態檔，加上環境變數覆寫

使用 `EngineMain` 啟動時，Ktor 會讀 `application.conf`。檔案裡的值可以被環境變數覆寫，語法是 `${?ENV_NAME}`：

```
ktor {
    deployment {
        port = 8080
        port = ${?PORT}
    }
}

db {
    url = "jdbc:postgresql://localhost:5432/shop"
    url = ${?DB_URL}
    password = ${?DB_PASSWORD}
}
```

本機開發用檔案裡的預設值，正式環境用環境變數蓋過去。`password` 刻意沒有預設值，因為不該有。

程式裡這樣讀：

```kotlin
val url = environment.config.property("db.url").getString()
```

這就是前面談過的那個差異：用 `embeddedServer` 的話設定寫在程式碼裡，用 `EngineMain` 的話設定放在檔案裡，部署時後者比較好管理。

## 打包成一個可執行的檔案

Ktor 的 Gradle 外掛提供 `buildFatJar` 任務，把應用程式與所有相依打成一個 jar：

```
./gradlew buildFatJar
java -jar build/libs/你的專案-all.jar
```

## 裝進容器

最小的 Dockerfile 可以只做三件事：基底映像檔、複製 jar、啟動指令。

```dockerfile
FROM eclipse-temurin:21-jre
COPY build/libs/*-all.jar /app/app.jar
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

密鑰不要寫進映像檔，要用執行時再傳進去：

```
docker run -e DB_PASSWORD=*** -e DB_URL=... -p 8080:8080 你的映像檔
```

映像檔一旦包進密鑰，等於每個拿到映像檔的人都拿到了密鑰。

這是最簡單的版本，不涉及多階段建置、映像檔瘦身與編排。先有一條能走通的路，再來優化它。
