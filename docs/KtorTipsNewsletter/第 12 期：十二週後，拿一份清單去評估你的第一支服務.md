# 十二週後，拿一份清單去評估你的第一支服務

十二週後，你手上多了一堆技巧，卻不知道自己的服務到底行不行。

這是十二期系列的最後一封信。系列從一支最小的路由，一路走到 Docker 映像檔，這封信不教新東西，只把走過的路收斂成一份可以直接對著專案檢查的清單。四個層次，十一個問題，每題用一句話問你。答不出來的那一題，就是你接下來要補的功課。

## 專案起手

路由與 Plugin 是整支服務的骨架，骨架歪了，後面每一層都跟著難改。

- 路由是否已經拆成 `Route` 的擴充函式，一個資源一個檔案？
- Plugin 的安裝順序，是你有意識安排的，還是碰巧跑得起來？

## 請求處理

這一層決定使用者看到的是服務，還是一頁堆疊追蹤。

- 缺欄位、多欄位、型別不符三種 JSON，你都用 `curl` 實測過，知道回的狀態碼與訊息嗎？
- 沒人接住的例外，回給用戶端的是固定格式的錯誤，堆疊追蹤只留在日誌裡嗎？
- handler 裡有沒有直接呼叫阻塞式函式庫？躲不掉的，是否用 `withContext(Dispatchers.IO)` 隔離了？

## 資料與依賴

Ktor 不會替你擋下這一層的錯，要靠你自己和 code review。

- 迴圈裡有沒有資料庫呼叫？有的話，那就是 N+1。
- 資料庫交易用的是協程友善的寫法嗎？
- `module()` 函式讀起來還看得懂嗎？物件組裝若已經痛到有兩個以上的訊號，再來考慮 Koin。

## 上線準備

前三層都對，這一層漏了，照樣出事。

- 該保護的路由，是否全部放進 `authenticate` 區塊？最近新加的那幾支有沒有漏？
- 資料庫密碼與 JWT 密鑰是否都來自環境變數，既不在程式碼裡，也不在映像檔裡？
- 核心路由有沒有 `testApplication` 測試，依賴可以替換成假的嗎？

## 這個系列沒有講的

清單看起來完整，但這個系列刻意留了幾塊沒碰，全部列入後續待辦：

- Ktor Client 與跨平台共享，也就是 Kotlin Multiplatform 那一側。
- WebSocket 與 Server-Sent Events。
- 可觀測性與壓測，包含日誌、指標與追蹤。
- OAuth 與第三方登入。

所以這份清單通過，只代表第一支服務有了站得住的基礎，離完整的正式環境還有距離。

## 回頭再答一次

系列的第 0 期，也就是那篇選型介紹文，留過三個問題：團隊有沒有人熟悉協程、服務是否真的有高併發或資源成本的壓力、你願不願意主動為依賴注入與 ORM 做技術選型。十二週前你可能是猜著答的，現在拿手上這支服務，再答一次。

謝謝你讀完這十二封信。如果身邊有朋友正在評估 Ktor，把這封信轉給他，這份清單比我的任何一句建議都更實用。

回信告訴我，這十一題裡你的專案答不出來的是哪一題。如果這封信是朋友轉給你的，歡迎訂閱，每週一封。
