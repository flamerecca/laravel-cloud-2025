# 登入之後，每個請求怎麼證明自己是誰

前端說：「登入成功了。」你打開日誌，看到那個人接下來的每一個請求，都被回了 401。

認證在 Ktor 裡沒有預設，要自己裝。好消息是，JWT 這條路只需要三個動作。先區分兩個詞：認證確認你是誰，授權決定你能做什麼。這封信只談前者。

JWT 是一段帶簽章的字串，伺服器驗證簽章，就能信任裡面的內容，不需要每次去查資料庫。

## 動作一，簽發

登入成功之後，用密鑰簽出一個 JWT，內容至少要有使用者識別與到期時間：

```kotlin
val jwt = JWT.create()
    .withIssuer(issuer).withAudience(audience)
    .withClaim("userId", user.id)
    .withExpiresAt(Date(System.currentTimeMillis() + 3_600_000))
    .sign(Algorithm.HMAC256(secret))
```

## 動作二，驗證

安裝 Authentication 這個 Plugin，宣告一個名為 `auth-jwt` 的驗證方案：

```kotlin
install(Authentication) {
    jwt("auth-jwt") {
        verifier(JWT.require(Algorithm.HMAC256(secret))
            .withIssuer(issuer).withAudience(audience).build())
        validate { cred ->
            if (cred.payload.getClaim("userId").asLong() != null) JWTPrincipal(cred.payload) else null
        }
    }
}
```

`verifier` 負責檢查簽章、簽發者與到期時間。`validate` 在簽章通過之後，讓你加上自己的判斷，回傳 `null` 就是不通過。驗證失敗時，預設會回 401。

## 動作三，保護路由

把要保護的路由放進 `authenticate` 區塊，並用 `call.principal` 取出使用者：

```kotlin
authenticate("auth-jwt") {
    get("/me") {
        val userId = call.principal<JWTPrincipal>()!!
            .payload.getClaim("userId").asLong()
        call.respondText("user $userId")
    }
}
```

沒有放進區塊的路由，任何人都可以呼叫，這是新手最容易漏掉的地方：加了認證，卻忘了把新路由放進去。

## 兩個提醒

密鑰不能寫死在程式碼裡，到期時間一定要設。範例裡的 `secret` 是示意，怎麼從環境讀進來，部署那一期會談。

這個系列刻意不談 OAuth 與第三方登入，那是另一條很長的路。
