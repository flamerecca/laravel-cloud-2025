day: 1
title: 卡關不是你不熟框架，是你撞上了邊界
core_goal: 讓讀者理解「找不到對應內建元件」不是自己知識不足，而是踩到框架設計邊界，並交給讀者一套判斷客製化程度該多深的自問流程
prerequisite_concepts:
  - 無，本期為系列第一期，不需要任何前置概念
  - 讀者已具備的背景僅限於「已經用 Filament 內建功能做出一套後台」這個前提，屬於招募門檻，非系列內定義的概念
estimated_word_count: 1200
sections:
  - heading: 具體場景切入
    purpose: 用讀者親身經歷過的挫折場景建立共鳴，讓讀者在前幾句話就認出「這封信在講我」
    key_points:
      - 描寫反覆搜尋官方文件、比對元件清單、確認某個需求真的沒有對應內建做法的具體過程，不要用抽象形容詞帶過，要讓讀者回想起自己那次盯著文件頁面發呆的畫面
      - 點出這種焦躁感常伴隨一個自我懷疑的念頭：是不是自己漏學了什麼、是不是有個隱藏參數沒找到
      - 這一段不需要提到 Filament 版本號或任何 API 名稱，場景要夠通用，讓不同背景的讀者都能對號入座
  - heading: 重新定義這個問題
    purpose: 把場景裡的焦躁感轉譯成一個可以理性處理的命題，說明這不是知識漏洞而是設計邊界
    key_points:
      - 明確區分「我不知道怎麼做」跟「這件事本來就不在框架預設的做法裡」是兩件不同的事，前者靠查資料解決，後者靠判斷層級解決
      - 帶出一句話說明這系列接續《Laravel Filament 從入門到實戰》完賽總結裡提到的兩類不擅長情境：高度客製化的視覺互動、非典型的後台操作型態，用一兩句話交代即可，不展開細節
      - 說明這系列要做的事，是把「該怎麼繞道」這個判斷具體接回來，示範怎麼走、也示範走到哪一步該承認這不歸框架管
  - heading: 建立判斷角度：這個需求離開多遠
    purpose: 交給讀者本期唯一要記住的自問流程，作為後續十一期的地基
    key_points:
      - 提出核心自問句：這個需求離 Filament 預設的做法有多遠
      - 說明「多遠」不是玄學，可以用具體徵兆判斷，例如是不是在調整一個既有元件的顯示方式、還是需要一個全新的互動邏輯、還是牽涉到框架完全沒設計過的操作型態，用生活化的方式描述層級遞增的感覺，不需要列出正式的分級表或名詞定義，那是後續幾期會逐步示範的內容
      - 強調越遠代表要動用的工具越底層，付出的代價，例如要理解的機制、要維護的程式碼，也越高，所以判斷這件事本身有價值，能避免每次卡關都從零開始用力氣去猜
      - 這期刻意不示範任何程式碼，純粹建立角度，要在文中明確表態這是特意的選擇，不是留一手
closing_hook: 邀請讀者回信說出自己被卡住的具體需求，並埋下伏筆：後面幾期會挑幾個讀者實際回報的案例來示範，讓讀者對接下來的內容產生「說不定我的問題會被寫進去」的期待感
