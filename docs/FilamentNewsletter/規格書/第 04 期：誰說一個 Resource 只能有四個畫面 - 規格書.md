day: 4
title: 誰說一個 Resource 只能有四個畫面
core_goal: 說明 Resource 預設的四頁 CRUD 骨架是預設值不是限制，示範怎麼在既有架構之外掛一個完全自訂的頁面
prerequisite_concepts:
  - 無強制前置概念，本期是獨立起點，但會呼應第 2、3 期建立的「客製化是在框架擴充點上動手，不是跳脫框架」的態度，作為銜接語氣，不重新解釋細節
estimated_word_count: 1400
sections:
  - heading: 一句話講清楚四個畫面是什麼
    purpose: 依照大綱「如果你沒看過前面幾期」原則，替沒有背景的讀者補上 Resource 預設四頁的定義
    key_points:
      - 用一句話列出列表、建立、編輯、檢視這四個預設畫面各自負責什麼，不需要展開背後的路由或類別結構
  - heading: 一個對不上任何一頁的需求
    purpose: 用具體例子建立「這次卡關等級不一樣」的認知，跟前三期做出區隔
    key_points:
      - 舉一個具體例子，例如需要跨資料操作、或畫面型態明顯不是在瀏覽單筆或多筆資料的功能，讀者會發現硬塞進列表、建立、編輯、檢視任何一頁都彆扭
      - 點出這是本系列深度階梯上第一次明顯跳階：前三期的客製化都還在「換一個元件」的層次，處理的是頁面裡的一小塊，這一期開始碰「換一種頁面型態」，處理的是整個頁面
  - heading: 骨架不會因為多一個房間而壞掉
    purpose: 消除讀者「動了預設架構會不會出事」的疑慮，建立信心
    key_points:
      - 說明掛一個全新頁面進 Resource，不需要更動或犧牲原本四頁的任何一頁，原有的列表、建立、編輯、檢視照常運作
      - 把新增頁面比喻成在原本的房子裡加蓋一個新房間，而不是拆掉重蓋，讓讀者理解這是加法而不是取代
  - heading: 示範方向：掛一個完全自訂的頁面
    purpose: 交代本期示範的技術內容層級
    key_points:
      - 說明會示範的層級是：頁面怎麼被註冊進 Resource、頁面如何取得路由與導覽入口、頁面內容跟預設四頁的關聯有多鬆散，概念層級說明，不寫出完整程式碼
      - 強調這頁面的內容本身可以完全自訂，不受限於預設頁面慣用的表單或表格結構，這一點跟前三期只是換元件的性質不同，要在文中明確講出這個差異點
closing_hook: 邀請有類似需求的讀者描述自己的場景，作為候選案例，並帶出下一期要處理的是另一種完全不同性質的客製化：視覺與品牌識別度的需求
