# 這一次，你要跳出 Schema 了

前五期我們一起把 Filament 的客製化摸了一輪，欄位怎麼繼承、表格怎麼呈現、頁面怎麼自訂、視覺怎麼分層，你應該已經有種「這個框架其實很聽話」的感覺。今天要說一個可能會讓你愣一下的事：這些招式，接下來都用不上了。

## 前面都在填空，這次的格子不夠用

一句話講完前五期：不管改欄位、調表格、加頁面還是分層視覺，你做的都是在 Filament 已經鋪好的 Schema 機制裡填空，這套宣告式規則負責描述畫面長什麼樣、有哪些欄位，你只需要決定格子裡放什麼。但接下來要處理的畫面，使用者得在同一頁動態新增、刪除、拖曳一堆互有關聯的區塊，切換一個開關要連動三個地方的顯示邏輯。這種複雜度不在「欄位長什麼樣」，而在「互動怎麼發生、狀態怎麼流動」，Schema 這套語法從一開始就不是為了描述這種題目而生的，硬塞只會讓你寫出一堆巢狀的 `live()` 跟 `afterStateUpdated`，比直接手刻一個 Livewire 元件還痛苦。

## 跳出機制，不等於跳出框架

這裡要講今天最重要的一句話：跳出 Schema 這套機制，不等於跳出 Filament。

你要做的，是寫一個完全獨立的 Livewire 元件，不透過 `Form`、不透過 `Schema`，該有的 `public $state`、`render()` 一樣不少，然後把它塞進 Panel 的某個頁面裡。Panel 依然認得這個元件，會把它當成頁面的一部分正常渲染，版面、導覽列、主題樣式一樣都在，使用者從外面根本看不出來這塊是「跳出機制」寫出來的。

代價也在這裡：從這一刻起，狀態管理跟畫面渲染的責任，從框架的手上回到你自己身上。前面五期 Schema 幫你處理好了值什麼時候該同步，現在你要自己決定 `public` 屬性怎麼宣告、`wire:model` 怎麼綁、畫面什麼時候該重新渲染。這不是跟 Filament 分手，是換一種相處方式：前面五期是「你填空、我運作」，這一期開始是「你自己扛這一塊的運作，我負責把它收進我的地盤，讓它看起來還是自己人」。你前面練出來的框架直覺，接下來全部還用得上。

## 示範方向：把獨立元件請進 Panel

今天不會寫出完整的互動邏輯，先講清楚要做到哪：一個完全不透過 Filament 表單機制定義的 Livewire 元件，怎麼被嵌進 Panel 的頁面裡，元件跟 Panel 之間的關係是什麼樣子。這是概念層級的說明，目的是先看清楚骨架長什麼樣。

這一步做完，你會得到一副骨架：元件能被裝進 Panel、能顯示出來、Panel 認得它。但骨架裡面是空的，那些讓人半夜想砸電腦的動態新增、刪除、連動邏輯，這一期還沒碰，因為光是把獨立元件正確請進 Panel，中間就有好幾個容易踩空的地方，值得單獨用一整期講清楚。這是地基，之後兩期要在上面蓋東西。

這一期是整個系列裡技術難度最高的一期，讀完覺得有點喘是正常的，不是你哪裡沒跟上。前面五期規則替你擋掉了大部分的坑，這一期你踩出規則之外，坑自然就多了。卡在哪個環節想不通，直接回信給我，我看到都會回。下一期要處理的，是這個獨立元件最容易讓人半夜爬起來 debug 的坑，狀態明明看起來對、畫面卻死活不更新的那種問題，順便把這一期你可能已經遇到的疑惑一起收一收。
