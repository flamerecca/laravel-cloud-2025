# 迴圈裡一筆一筆查，資料庫被打爆了

列表頁十筆資料時跑得好好的，一百筆就慢到要等。

程式碼看起來沒有任何問題，每一行都很正常。問題不在某一行，而在整個迴圈合起來做了什麼。

## 先把日誌打開

要抓這個問題，第一步是看見 Exposed 實際送了什麼 SQL：

```kotlin
transaction {
    addLogger(StdOutSqlLogger)
    val snippets = Snippet.all().toList()
    snippets.forEach { println("${it.title}: ${it.tags.map { tag -> tag.name }}") }
}
```

跑一次，數一數主控台印出了幾條 SELECT。你會看到一條查全部片段，然後是每一個片段各一條查標籤的 SELECT。

## N+1 的樣子

假設有十個片段。結果是一條查片段，加上十條各自查標籤，共十一條。一百個片段就是一百零一條。查詢次數跟筆數成正比，筆數一長，就把資料庫與網路往返的時間全部吃掉。這就是 N+1：一次查列表，加上 N 次查關聯。

Exposed 不會替你警告這件事。程式正確，只是慢。能抓到它的，是日誌與你對查詢次數的習慣。

## 一次載入關聯

用 eager loading，告訴 Exposed 要連關聯資料一起載入：

```kotlin
transaction {
    addLogger(StdOutSqlLogger)
    val snippets = Snippet.all().with(Snippet::tags).toList()
    snippets.forEach { println("${it.title}: ${it.tags.map { tag -> tag.name }}") }
}
```

再數一次日誌。查詢次數不再跟筆數一起長，通常只剩下固定的幾條。

## 一個習慣

開發時，凡是列表頁或迴圈裡讀取了關聯資料，就打開日誌看一次。請用你實際數出來的數字，不要憑感覺。這個習慣，比記住任何 API 都有用。
