# 更新與刪除，忘了條件會發生什麼事

你只是想改一筆，結果整張資料表的標題，都變成了同一個。

更新與刪除跟新增、查詢不一樣：寫錯了，影響的不只是你眼前那一筆。這封信先看正確的寫法，再故意示範一次最常見的錯誤。

## 正確的寫法

```kotlin
transaction {
    Snippets.update({ Snippets.id eq 1 }) {
        it[title] = "新的標題"
    }
    Snippets.deleteWhere { Snippets.id eq 2 }
}
```

`update` 的第一個參數是條件，後面的區塊指定要改的欄位。`deleteWhere` 的區塊就是刪除條件。兩者都會回傳受影響的筆數，這個數字很有用。

## 漏掉條件

下面這段看起來只差一個參數：

```kotlin
transaction {
    val affected = Snippets.update {
        it[title] = "全部都變成這個"
    }
    println("改了 $affected 筆")
}
```

沒有條件，所以每一列都被改了。程式不會有任何警告，編譯器也不會，因為這是合法的寫法。請只在拋棄式的 H2 資料庫上嘗試這個示範，絕對不要在有真實資料的地方試。

## 一個便宜的保險

更新或刪除之前，用相同的條件先寫一次查詢：

```kotlin
transaction {
    val count = Snippets.selectAll()
        .where { Snippets.id eq 1 }
        .count()
    println("會影響 $count 筆") // 預期是 1
}
```

確認筆數與內容符合預期，再把查詢換成更新或刪除。多寫三行，換來的是每一次都能先看見影響範圍。這個習慣比任何框架提供的保護都管用。

資料會新增、查詢、修改、刪除了，用的都是 DSL。下一封信，我們換一種風格，用物件來操作同一張資料表。
